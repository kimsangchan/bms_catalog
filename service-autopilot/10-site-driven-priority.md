# 현장 물량으로 정한 수집 우선순위

**한 줄:** 우리가 모은 것과 현장에 깔린 것이 **거의 반대**다.
현장에 **팬 305대·공조기류 242대**가 있는데 카탈로그는 팬 4모델·공조기 9모델이고,
**냉동기는 현장 12대에 카탈로그 70모델**이다. 냉각탑 16대·열교환기 26대는 **0모델**.

작성 2026-09-04. 근거는 사용자가 제공한 **실제 구축 현장** 포인트리스트다.

---

## 왜 이걸 셌나

지금까지 수집 순서는 **벤더 문서가 열려 있는 순서**였다(JCI 포털이 크니 JCI부터).
그건 "우리가 받기 쉬운 순서"지 "현장에 많은 순서"가 아니다.
현장 포인트리스트에는 **실제로 무엇이 몇 대 깔렸는지**가 있으므로 그것으로 다시 정한다.

## 우선순위

1. **팬(급기·배기, 인버터)** — 현장 305대. 가장 많은데 4모델뿐이다.
2. **공조기·외조기** — 215 + 27대. 국내 벤더(신성엔지니어링·센추리·우원기계)가
   계획서 1순위로 이미 지목돼 있다.
3. **VRF/DVM** — 대수는 미산출이나 캠퍼스의 **냉각탑·열교환기가 "DVM용"**이다.
   지금 2모델·0점이라 **LG BACnet 165점 취입이 곧 첫 실체**가 된다.
4. **펌프** — 96대, 7모델. 인버터 펌프 위주로 보강.
5. **열교환기·냉각탑** — 26·16대인데 0모델. 빈 계열 중 물량이 확인된 둘.
6. ⬇ **냉동기는 멈춘다** — 현장 12대에 70모델 14,520점이면 충분하다.

## ⚠ 정정 — "팬·공조기 벤더 문서"는 오브젝트 목록의 답이 아니다

수집에 들어가기 전에 **현장에서 그것들이 어떻게 붙어 있는지**를 셌다. 결과가 순서를 바꿨다.

| | |
|---|---|
| **팬은 통신하지 않는다** | 배기휀·급기휀은 DDC 하드와이어 DI/DO 다(`I_15_DI3_A120_1-EF-175-STS2`). 벤더 오브젝트 목록이 필요 없다 |
| **공조기 본체도 통신하지 않는다** | 공조기류 4,922점 중 **하드와이어 70.0%** · 통신 22.2% — 그 통신분이 **전부 인버터**(`INV_*`)다. 온도·습도·밸브·댐퍼는 전부 DDC 직결 |

즉 **오브젝트 목록이 필요한 것은 통신하는 장치**뿐이다. 삼성 캠퍼스에서 세면:

### 그래서 문서는 두 갈래로 나눠 모은다

| 목적 | 필요한 문서 | 대상 |
|---|---|---|
| **오브젝트 매핑** | 통신 매뉴얼(레지스터·오브젝트 표) | VAV 컨트롤러 · **인버터** · 부스타 보일러 |
| **시뮬레이터 정격** | 제품 카탈로그(풍량·정압·코일 능력) | 공조기 제조사 신성엔지니어링 · 센추리 · 우원기계 |

⚠ 인버터 222대와 VAV 399대의 **브랜드가 현장 데이터에 없다.** 포인트 이름
(`DCLINK_VOLTAGE` · `Occupied Max Set Flow`)은 여러 벤더가 공통으로 쓰는 어휘라
그것만으로 못 가린다. **현장을 구축한 쪽이 아는 정보다** — 물어서 정한다.
(브랜드가 나온 것은 부스타·Trane·삼화 셋뿐이다.)

⚠ 신성엔지니어링(`ishinsung.com/product/catalog`)은 **검색해야 내려받는 동적 페이지**이고
센추리(`century-korea.com`)는 **SSL 오류**로 열리지 않았다. 둘 다 브라우저가 필요하다
— 저장소가 말하는 "page 방식" 이다.

**닫은 것 — 인버터 222대 · `VC-100` VAV 399대 · `WPC-100` 344점**

주어진 자료로는 **제조사를 알 수 없다.** 다음을 전부 확인했고 전부 비었다:

| 뒤진 곳 | 결과 |
|---|---|
| 포인트 이름 | `DCLINK_VOLTAGE` · `Occupied Max Set Flow` — 어느 벤더나 쓰는 일반 어휘 |
| **LS H100 매뉴얼과 글자 대조** | **0건 일치.** H100 은 `DC Link` · `Output Current` 로 띄어 쓴다 |
| 이름의 성격 | 215대가 **오타까지 같다**(`INV_HEATsink TEMP`) — 펌웨어가 준 이름이 아니라 **SI 가 붙인 템플릿 이름**이다. 그래서 이름으로는 영영 못 가린다 |
| 장치 이름 뒤 숫자 | `VC-100_7309` 의 7309 는 BACnet 인스턴스지 제조사 코드가 아니다 |
| 인버터 한글 설명 | **0종** |
| 나이아가라 내보내기 `Type` 열 | `bacnet:…Descriptor` — SI 가 **상위로 내보내는** 서버 쪽이라 하위 장치가 안 나온다 |
| 자료 전체의 BACnet 장치 속성 | `Vendor_Name` · `Model_Name` 항목이 **한 건도 없다** |
| 웹 검색 `VC-100` | 안 나온다(국내 유통명이거나 SI 내부 명명으로 보인다) |

### 확정하려면 — 현장에 안 가고, 협조 없이 되는 길

나이아가라가 **BACnet**이므로 장치가 제조사를 스스로 보고한다. 그 값은
**Workbench 안에서 읽힌다** — 출입도 제3자 협조도 필요 없다.

    Config → Drivers → BacnetNetwork → (해당 장치) → Property Sheet
      Vendor Name · Vendor Id · Model Name · Firmware Rev

`Bacnet Device Manager` 뷰의 목록에도 Vendor/Model 열이 있다.
`Vendor Id` 는 ASHRAE 가 부여하는 번호라 숫자만 나와도 공개 목록에서 이름이 나온다.

**이 두 줄(인버터 1대·VC-100 1대의 Vendor/Model)만 있으면 문서 수집이 바로 이어진다.**

## 제조사를 채워 넣었다 — 확정이 아니라 **후보**다 (2026-09-07)

사용자 지시: *"제조사 내가 알아올 방법이 현재 없다 — 자료·도면·포인트와 이 정도 규모
현장에서 점유율 높은 벤더로 채워 둬라."* 그래서 채웠고, **근거의 세기를 함께 적는다.**
확정으로 읽고 문서를 취입하면 안 된다 — 취입 전에 Vendor Name 두 줄로 확인한다.

| 장치 | 대수 | 후보 | 근거 | 세기 |
|---|---|---|---|---|
| **인버터** | 222 | **Danfoss VLT HVAC Basic Drive FC 101** | 포인트 이름 `INV_SPEED_FC101` 이 **762회** — 다른 `INV_*` 6점과 **같은 횟수**다. 한 대의 설비 태그라면 1회여야 한다. 즉 **템플릿 이름 자체에 모델명이 박혀 있다.** `FC-101` 은 Danfoss VLT HVAC Basic Drive 의 형식명이고, 이미 받아 둔 `DKDDPFP100A402_HVAC_Basic.pdf` 가 그 제품 자료다 | **강함** (정황) |
| **VAV/유량 컨트롤러** | 399 | **나라컨트롤(Nara Controls)** — 2순위 하니웰 Spyder · JCI | 이름(`VC-100`·`WPC-100`)은 국내 유통명이고 웹에 안 나온다. 포인트 이름 여섯(`Occupied Max Set Flow`·`Analog Damper Output`·`Control Mode Config` …)을 **우리 카탈로그 36,876점 전수와 대조해도 0건**이라 보유 벤더 중엔 없다. 국내 대형 캠퍼스 BAS 점유·자체 컨트롤러 보유로 고른 **점유율 추정**이다 | **약함** (점유율 추정) |

⚠ `FC-101` 이라는 토큰 자체는 현장에 5,342회 나오지만 **대부분 팬코일 태그**(`FC-`)다.
   인버터 근거는 그 숫자가 아니라 `INV_SPEED_FC101` 쪽이다 — 헷갈리지 말 것.

**`ICU` 는 컨트롤러다** (2026-09-07 사용자 확인). 카탈로그·현장자료·웹 어디에도 0건이라
약어의 정체를 못 짚고 있었다. 컨트롤러라는 것까지는 확정 — 어느 제조사의 무엇인지는 미상.
