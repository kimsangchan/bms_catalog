# PDF 파서 대조 — PyMuPDF `find_tables()` (현행) vs opendataloader-pdf

- 날짜: 2026-08-20
- 물음: 표 인식을 [opendataloader-pdf](https://github.com/opendataloader-project/opendataloader-pdf)
  로 갈아탈 이유가 있나.
- 결론: **회수 능력은 동률**(행일치 99.5%). 갈아탈 근거는 회수율이 아니라
  **셀 내용의 정확도·읽기 순서·속도·문서 구조**다. 아직 채택하지 않았다.

## 시험 조건

6문서 · 698쪽 · 확정 포인트 **7,440점** (JCI·Swegon·Systemair·Trane·Daikin·AAON).
정답 키는 `pipeline/data/models` 의 확정 포인트 — `validate.py` 게이트 + 교차 대조 +
사람 검수를 통과한 것이다. 두 파서를 **문서 전체**에 돌렸다(페이지 범위 지정 없이).

## 수치

| | PyMuPDF (현행) | ODL default | ODL cluster |
|---|---|---|---|
| 이름 회수 | 7,438 (100.0%)* | 7,410 (99.6%) | 7,410 (99.6%) |
| 표 | 722 | 726 | 727 |
| 행 | 15,373 | 15,505 | 15,508 |
| 시간(698쪽) | 211초 | **50초** | 52초 |

\* 정답 키를 PyMuPDF 기반 추출기로 만들었으니 이 100% 는 거의 항진명제다. 편향 없는
수치는 **행일치 99.5%**(7,404/7,438) — 같은 포인트에 두 파서가 같은 행을 만든다.

차이 44건을 원문까지 따라간 결과: **불일치 6건은 파서 오류가 아니고**(같은 이름이
여러 표에 나와 서로 다른 표를 맞댄 것), **28건은 PyMuPDF 오류**, ODL 단독 손실 **0건**.

`table_method` 는 이 코퍼스에서 무의미하다(default 726 vs cluster 727).

## 검증된 실제 차이 — 전부 ODL 우세

1. **아래첨자를 PyMuPDF 가 깨뜨린다.** Swegon `ReCO₂` →
   PyMuPDF `'ReCO heat level\n2'` · ODL `'ReCO2 heat level'`.
   같은 주소(`3x0096`)·같은 나머지 셀로 대조 확인했다.
   ⚠ **오염된 이름 28건이 이미 확정 데이터에 들어가 있다** — 각주 번호로 보이는 꼴이라
   검수를 통과했다. 파서 교체와 무관하게 고쳐야 한다.
2. **다단 열거 셀의 읽기 순서.** Trane `MI-10105`(모델 59종) — PyMuPDF 는
   `1 = CVHF 31 = HSWA / 2 = CVGF 32 = ACRA …` 로 두 단을 뒤섞는다. ODL 은 `1 → 59`
   순서. 글자 수는 685 로 같으니 손실이 아니라 순서 문제이고, MV/MI 상태값 파싱에
   직접 걸린다.
3. **줄바꿈 처리** — 설명문의 줄바꿈을 ODL 은 한 줄로 잇는다(PyMuPDF 는 `\n` 잔류).
4. **속도 4.2배**, 그리고 **문서 구조**(heading/paragraph/list/caption + 읽기순서
   xycut)를 준다. `scan_jci.py` 의 "200쪽 IOM 본문에 묻힌 포인트 표 찾기" 에 쓸 수 있다.

## 전환 비용·함정

- **Java 21 필요.** 이 PC 는 PATH 에 `C:\Windows\system32\java.exe`(Java 8) 가 섞여
  있어, 파이썬 래퍼가 `java` 를 그대로 넘기면 `UnsupportedClassVersionError` 로 죽는다.
  실패가 간헐적으로 보여 처음엔 동시 실행 탓으로 오진했다. **java 경로 고정 필수.**
- **출력 트리를 일반적으로 훑어야 한다.** 열쇠를 열거하면 조용히 유실된다 — 이번에
  세 번 밟았다:
  ⑴ 셀 글자는 `text` 가 아니라 **`content`** (회수율이 0% 로 나왔다)
  ⑵ 리스트형 셀은 `kids` 가 아니라 **`"list items"`** (상태값·범위 열이 통째로 비어
     "ODL 이 열을 버린다" 고 오판할 뻔했다)
  ⑶ 표가 다른 표의 셀 안에 **중첩**된다 (`kids` 만 따라가 표를 덜 셌다)
- **전환 범위**: `find_tables` 호출부 20곳 — `extract`·`specs`·`ingest_jci`·`scan_jci`·
  `requirements`·`crosscheck` + `vendor_*` 9개. 규칙 3(추출기를 고치면 회귀를 확인한다)
  이 걸리는 종류의 변경이다.

## 다시 재려면

대조 하네스는 스크래치패드에 있었고 저장소에 남기지 않았다(원문 PDF 에 의존한다).
재현 절차만 적어 둔다 — 문서 6건을 골라 두 파서로 문서 전체를 돌린 뒤,
`data/models` 의 확정 포인트를 정답 키로 삼아 ⑴ 이름이 어느 행에든 나오는가
⑵ 같은 포인트의 행 내용이 두 파서에서 같은가 를 센다. 이름으로 행을 찾으면 정답 키가
물려받은 오류를 그대로 따라가므로, 갈린 행은 **첫 칸(주소)으로 짝지어** 셀 단위로 본다.
