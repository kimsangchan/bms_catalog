# PRD — BMS 장비 스펙 기준 DB (`bms-equip-spec-registry`)

- 작성 2026-07-27 · service-autopilot A3 · 선행: `02b-blindspot-register.md`
- 스코프 정정 반영: **카탈로그(표준 스펙) 중심 + BMS 시스템 적용**. 포인트리스트는 커버리지 측정 근거.

## 배경

빌딩 자동제어 장비의 스펙·포인트·태그가 현장마다 사람 손으로 다시 만들어진다. 실측으로 확인된 상태
(`evidence/pointlist-profile-summary.md`, 서울캠퍼스 1,027파일 / 114,962포인트 전수):

- 단위가 **79.6% 공란**이고, 있는 것도 `℃`/`°C`, `CMH`/`m³/hr`로 표기가 갈린다 (O-02·O-04).
- 알람 등급 비영값 **0건**, 트렌드 주기 **전부 공란**, 상태 enum 사실상 미사용 (O-07·O-08).
- 포인트 이름에 Modbus 레지스터 주소가 박혀 있다 (`환수온도40036`) — 통신맵에 있어야 할 정보가 이름으로 샜다 (O-16).
- 장비 이름에서 모델을 확정할 수 없다 — `UC-800`(실모델)과 `AH-114`(태그번호)가 같은 패턴으로 섞인다 (5절).

즉 **현장 데이터에는 스펙이 없다.** 스펙은 제조사 문서·통신맵·표준에 있고, 그것을 기준 데이터로 만들어
BMS에 넣어주는 주체가 없어서 매 현장이 반복 노동을 한다. 이 서비스가 그 주체다.

참조 표준: [Project Haystack Equips](https://project-haystack.org/doc/docHaystack/Equips) ·
[Haystack AHUs](https://project-haystack.org/doc/AHUs) · [Brick 개념](https://docs.brickschema.org/brick/concepts.html) ·
[BACnet 오브젝트 타입](https://docs.chipkin.com/articles/bacnet-object-types-properties-reference/) ·
[ASHRAE Guideline 36-2024](https://webstore.ansi.org/standards/ashrae/ashraeguideline362024)(유료 — 조항 참조만).

## 용어 사전 (문서 간 드리프트 방지 — 이 정의만 사용)

| 용어 | 정의 | 아닌 것 |
|---|---|---|
| **분류**(equip category) | 장비의 표준 종류. 3레벨 트리 (대·중·소) | 현장 장비 1대가 아니다 |
| **모델**(equip model) | 제조사 + 모델코드로 식별되는 실제 제품 | `AH-114` 같은 현장 태그번호가 아니다 |
| **포인트 타입**(point type) | 표준화된 계측·지령·설정값의 종류 (예: 급기온도) | 현장 오브젝트가 아니다 |
| **포인트 프로파일**(point profile) | 분류별로 "어떤 포인트 타입이 필수/권장/선택/금지인가" + 기본값 | 모델 통신맵이 아니다 |
| **모델 포인트**(model point) | 특정 모델이 실제로 노출하는 포인트 + 통신 주소 | 표준 포인트 타입이 아니다(연결될 뿐) |
| **릴리스**(release) | 카탈로그 전체의 동결된 버전 (semver + 내용 해시) | 초안 상태 카탈로그가 아니다 |
| **적용**(apply) | 릴리스의 스펙을 대상 BMS에 오브젝트·태그·기본값으로 투입하는 행위 | 실시간 값 연동이 아니다 |
| **대상 시스템**(target system) | 적용받는 BMS (NEUROS 인스턴스 / 시뮬레이터) | 현장 DDC가 아니다 |
| **근거**(evidence) | 스펙의 출처 문서 메타 (경로+해시+발행자). 원본은 보관하지 않음 | 문서 파일 자체가 아니다 |

## 제품 목표 (3개, 직교)

| ID | 목표 | 판정 축 |
|---|---|---|
| **G1 표준** | 공조/HVAC 자동제어 장비를 분류→모델→포인트까지 **근거가 붙은 단일 기준**으로 정의한다 | 내용의 완전성·출처 |
| **G2 적용** | 그 기준을 BMS에 **사람 손 없이 투입**한다 (오브젝트·태그·단위·기본값 자동 생성) | 적용의 정확성·멱등성 |
| **G3 재사용** | 같은 기준을 **어떤 BMS든 동일 버전으로** 소비한다 — NEUROS·시뮬레이터·타사 BMS를 어댑터 추가만으로 지원(폐쇄망 포함) | 버전 고정·시스템 중립·이식성 |

| **US-02** | As a 기준데이터 관리자, I want 제조사 모델의 정격 스펙과 통신맵을 근거 문서와 함께 등록하고, so that 현장 엔지니어가 매뉴얼을 다시 뒤지지 않는다 | **P1** |

| **US-04** | As a 구축 엔지니어, I want 기존 현장을 카탈로그와 대조하고, so that 결손·초과·단위 불일치를 리포트로 받는다 | P2 |
| **US-05** | As a 시뮬레이터 개발자, I want 릴리스 번들로 장비 동작 모델을 시딩하고, so that 관제와 시뮬레이터가 같은 장비 정의를 쓴다 | P2 |
| **US-06** | As a 폐쇄망 현장 담당, I want 서명된 오프라인 번들로 카탈로그를 갱신하고, so that 인터넷 없이 표준을 최신화한다 | P3 |
| **US-07** | As a 타 BMS 도입 담당, I want **어댑터만 추가해서** 우리 표준 카탈로그를 그 시스템에 투입하고, so that NEUROS 전용이 아닌 자산이 된다 | **P1** |
| **US-08** | As a 기준데이터 관리자, I want 보유한 현장 포인트리스트로 **우리 표준이 실제 현장을 몇 % 설명하는지** 채점하고, so that 카탈로그의 결손을 만들면서 바로 찾는다 | **P1** |

**P1만으로 MVP 성립**: US-01(카탈로그 정의) + US-02(모델 스펙) + US-03(적용) + US-07(시스템 중립) +
US-08(커버리지 검증) = "표준을 만들고 → 실제 현장 데이터로 검증하고 → 어떤 BMS든 투입"이 끝까지 돌아간다.
대조(live 시스템 스캔)·시뮬레이터·오프라인은 없어도 가치가 성립한다.

## UI 방향

내부 관리 도구 3화면만. NEUROS와 동일 스택(React 19·TS strict·Vite·Tailwind 4 CSS 변수 테마)과
`DESIGN_GUIDE.md` 토큰을 재사용한다 — 별도 디자인 시스템을 만들지 않는다.

| 화면 | 핵심 | 밀도 |
|---|---|---|
| 카탈로그 편집기 | 분류 트리(좌) + 포인트 프로파일 표(우), 등급·기본값 인라인 편집 | 높음 (데이터 그리드) |
| 모델 스펙 편집기 | 모델 헤더 + 정격 속성 표 + 통신맵 표 + 근거 패널 | 높음 |
| 적용 계획·미리보기 | 계획 구성 → **diff 미리보기(생성/갱신/충돌)** → 승인 → 실행 진행률 | 중간 |

`frontend-design-taste` dial: **밀도 high · 모션 low**(관제 운영자용 화려함 불필요) · 색은 상태 의미(생성/충돌/결손)에만.

## 범위 밖 (non-goals)

합리적으로 목표일 수 있었지만 명시적으로 제외한다:

1. **실시간 값 수집·트렌드 저장** — NEUROS 책임. 기준 DB는 설계 시점 데이터만 보유.
2. **제어 로직 실행·최적화** — 시뮬레이터와 현장 DDC 책임. 우리는 시퀀스 *참조*만 보유.
3. **장비 조달·견적·재고·자산 감가** — 스펙 카탈로그와 구매 시스템을 섞지 않는다.
4. **BIM/IFC 모델 관리** — 공간 정보는 참조 키만.
5. **ASHRAE G36 등 유료 표준 원문 재현** — 조항 번호와 자체 요약까지.
6. **현장 포인트리스트 전량 이관·정리 서비스** — 취입은 **카탈로그 커버리지 채점**과 후보 제안 목적에 한정.
   현장 데이터를 우리가 대신 정리해주는 서비스가 아니다.
7. **다국어** — 한국어 표시명 + 영문 코드 병기까지. 그 이상은 추후.
8. **대상 시스템 DB 직접 쓰기** — 어떤 BMS든 **어댑터 경유**만. 특정 DB 스키마에 결합하면 확장성이 죽는다 (A-07).
9. **BMS 자체 기능 대체** — 우리는 스펙을 넣어줄 뿐, 관제 화면·제어 로직·값 수집은 각 BMS가 한다.
