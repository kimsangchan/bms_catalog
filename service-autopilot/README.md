# BMS 장비 스펙 기준 DB — 기획·설계 산출물

service-autopilot 파이프라인 산출물. 서비스 slug `bms-equip-spec-registry`, 테이블 접두 `bes_`.

## 한 줄 정의

**BMS/자동제어 장비의 표준 스펙(분류 → 모델 → 정격·성능 → 통신 → 포인트 프로파일 → 태그 → 시퀀스)을
기준 데이터로 보유하고, 이를 BMS 시스템(NEUROS·자동제어 시뮬레이터)에 적용(투입)한다.**

## 스코프 정정 (2026-07-27)

착수 시점(2026-07-23) 조사는 **보유 포인트리스트를 정규화·매핑하는 방향(bottom-up)** 으로 잡혀 있었다.
사용자 지시로 다음과 같이 축을 바꿨다:

| 구분 | 정정 전 (07-23) | 정정 후 (07-27, 현행) |
|---|---|---|
| 중심축 | 현장 포인트리스트 취입 → 정규화 → 표준 매핑 | **장비 스펙 표준 카탈로그** 구축 → BMS 시스템에 **적용** |
| 포인트리스트 위치 | 1차 입력 원천 | **카탈로그 커버리지를 실측하는 근거**(P2로 강등) |
| 산출 가치 | 기존 현장 데이터 정리 | 신규·기존 현장에 **표준을 투입**(포인트 생성·태깅·기본값 주입) |
| 범위 깊이 | 장비 분류 + 태깅 | **모델별 spec까지** (Q1 답변), 도메인은 **공조/HVAC 우선** |

정정 사유와 기각 대안은 `decision-log.md` D-005 참조.

### 화면 다시 만들기

`08-equip-spec-tag-catalog.md`(장비 공통)나 `evidence/models.py`(모델 값)를 고친 뒤:

```bash
cd evidence && PYTHONUTF8=1 python build_browser.py && PYTHONUTF8=1 python gen2.py
```

화면 설계 기준: `frontend-design-taste` **관제/대시보드 프로파일**(밀도 8·모션 2·편차 3) +
`service-autopilot/references/ux-principles-kr.md`. 적용 내역은 아래 표.

| 원칙 | 적용 |
|---|---|
| L-03 한 패널 한 목적 | 포인트·사양·모델을 **탭으로 분리** (이전엔 한 화면에 다 쏟음) |
| L-04 7±2 청킹 | 종류·등급 **필터 칩**으로 긴 표를 잘라서 봄 |

## 최상위 설계 전제 — 2026-07-27 사용자 확정 완료

| # | 전제 | 상태 |
|---|---|---|
| **A-06** | 기준 DB는 **PostgreSQL 단일, 사내 중앙 1인스턴스**(현장 미설치). 폐쇄망은 서명 번들 반입 → NEUROS의 MSSQL/PostgreSQL 이중 DDL 부담을 지지 않는다 | ✅ 확정 |
| **A-07** | 적용은 **시스템 중립 표준 페이로드 + 어댑터 SPI**. NEUROS·타사 BMS·시뮬레이터 모두 어댑터 추가만으로 지원하고, 대상 DB 직접 쓰기는 금지 | ✅ 확정 (**확장성 요구로 강화** — D-010) |
| **A-08** | 적용은 **preview 승인 → execute 2단계** — 무단 대량 쓰기를 구조적으로 차단 | ✅ 확정 |
| **D-014** | **포인트리스트 검증(취입+커버리지 채점)을 P1로 승격.** 미설명 포인트 목록 = 카탈로그 결손 작업목록 | ✅ 확정 |

포인트리스트의 역할: **원천이 아니라 채점표**다 — 조사·표준화한 장비 스펙과 태그가 실제 현장에 적용되는지
확인하는 수단(SC-003 커버리지 ≥80%, EP-64 `unexplained[]`).
